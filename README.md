# TypeLex

**用模拟键盘把英语和日语单词打进肌肉记忆。**

TypeLex 把「打字练习」和「背单词」合成同一件事：你在一个按真实布局渲染的模拟键盘上敲出单词，
旁边的卡片同时告诉你它的词性、释义、例句、同根词和易混词。打错的词会被排进更早的复习队列。

纯前端、无后端、无账号 —— 所有进度都存在浏览器本地。

**在线使用：** https://fanquanpp.github.io/typelex/
**源仓库：** https://github.com/fanquanpp/typelex
**English:** [README.en.md](README.en.md)

## 它解决什么问题

大部分打字练习网站让你打随机字母或随机文章，打完什么也没记住；大部分背单词 App 让你点选项，
手指从未真正拼写过那个词。而「拼写」恰恰是记忆里最难的一环。

TypeLex 的做法是：**想记住一个词，就把它完整打出来**。于是打字练习的每一秒都在为词汇服务，
词汇复习的每一次都在训练手指。

## 功能

**七种练习模式**

| 模式 | 做什么 |
| --- | --- |
| 随机 | 从所选词库随机抽词，覆盖面最广 |
| 顺序 | 按字母顺序推进，进度可续，适合系统过一遍词表 |
| 专项 | 按词性或主题集中突破：形容词、介词、不规则动词、易混词…… |
| 句子 | 打整句真题例句，练节奏、标点与 Shift |
| 弱键特训 | 按你的逐键速度与错误率组词，专治拖后腿的字母 |
| 记忆复习 | 只复习到期的卡片，答对拉长间隔，答错缩短 |
| 日语罗马音 | 输入罗马音打日语单词，假名、汉字、罗马音与中文释义同步显示 |

**词条卡片不只是「单词 + 释义」**

英语卡片（挂在挂绳上会摆动的实体证件卡）面：音标（英/美）、词性、中英释义、例句（含中文翻译）、
常用搭配、**同根词家族**（happy → happily → happiness）、同近义词、易混词对照、
记忆法（词根拆解或联想）以及四六级真题片段，正反面都能看。

日语卡片：假名、汉字写法、罗马音与中文释义。

**其它**

- **模拟键盘**：3 个预设（办公薄型 / 87 键 TKL / 60% 客制化）× 6 种布局，4 种视角可选
- **逐键数据**：每个键的用时与错误率都会记录，键盘热力图与弱键特训都基于它
- **指法着色**：按负责的手指给键帽上色，左右食指各管两列，小指兼管 Shift
- **实时反馈**：下一个键在键盘上脉冲高亮，打错时红闪，正确时按键下沉
- **整词可见的虚影**：待输入的字母全部以淡色虚影排在格子里，打对一个就点亮一个（不再是空格子挨个出现）
- **打完切换方式**：设置里可选「自动」或「回车」——自动打完立刻进下一个词，回车则停在原地、看清刚打的词再按 Enter
- **背光模式**：关闭 / 按键响应 / 弱键标记，在键盘实验室里即时预览
- **英语音标表**：48 个音标按元音 / 清辅音 / 浊辅音分组，以「音标 / 例词 / 常见字母组合」三列对照，可切换英式与美式写法
- **双色主题**：深色 / 浅色，随系统偏好初始化
- **进度持久化**：刷新页面会回到原来的位置，包括未完成的练习队列
- **合成按键音**：Web Audio 实时合成，可选线性轴 / 茶轴 / 青轴 / 剪刀脚音色，不加载任何音频文件

## 键盘

键盘用 DOM/CSS 渲染，不再依赖 WebGL：同一套按 ANSI 单位（1u = 19.05mm）定义的布局数据
渲染成绝对定位的键帽，以浅倾角透视（`preserve-3d`）加指针视差呈现层次；按键动画直接写内联样式，
不经过 React 状态，一次敲击零重渲染。

| 预设 | 布局 | 键帽体系 | 背光 |
| --- | --- | --- | --- |
| 办公薄型键盘 | 104 键全尺寸 | 低键程剪刀脚 | 无 |
| 87 键机械键盘 | 87 键 TKL | Cherry 高度 | 白色 |
| 60% 客制化键盘 | 60 键 | Cherry 高度 | 无 |

- 布局数据共 6 套：104 / 98 / 87 / 75 / 65 / 60%，行错位 0.5u / 0.25u / 0.5u，
  Backspace 2u、Tab 1.5u、Caps 1.75u、Enter 2.25u、左 Shift 2.25u、右 Shift 2.75u、空格 6.25u
- 键帽弧度按 OEM / Cherry / 巧克力 / 低键程四种体系逐行定义高度与倾角
- 4 种视角（斜视 / 俯视 / 正视 / 近景），在键盘实验室里切换
- 背光三态：关闭 / 按键响应（打字时亮）/ 弱键标记（用你的错误率数据点亮最弱的键）

## 技术栈

- **React 19** + **TypeScript** + **Vite 8**
- **Three.js** —— 仅用于词库页的 Lanyard 挂绳证件卡
- **Zustand** —— 状态与 localStorage 持久化
- **React Router** —— HashRouter，保证任意路由刷新后都能恢复
- **motion** —— 少量交互组件（顶部导航胶囊、橡胶分段选择器）的弹簧动效
- 无 UI 组件库、无 CSS 框架：设计系统是手写的 CSS 自定义属性
- 控件全部自绘：下拉用 `GlideSelect`（原生 `<select>` 已全部替换），图标按钮的提示用
  `WarmTooltip`（不再依赖原生 `title`）
- 字体自托管（`@fontsource-variable`：Sora / Manrope / JetBrains Mono），中文用系统字体栈

### 字体与可读性

界面的字阶从 **12px 起跳**（`--text-2xs`），因为这是中文优先的界面：汉字在 12px 以下，
计数器（笔画间的空白）会在 Windows 的微软雅黑与 macOS 上一起糊掉。全站只在这一处定尺寸，
组件不再写死 px：

- 字阶：12 / 13 / 14 / 15 / 17 / 19 / 24 / 32px，标题级用 `clamp()` 随视口放大
- **页头标题只有两级**：功能页一律 32px（与词库页一致），三级页（练习会话 / 五十音图 / 词表 /
  逐键分析 / 练习历史）等比例降为 24px；首页大标题属于 hero，不算页头
- **间距**：页级区块之间 40px，区块内的卡片之间 32px、标题到内容 24px
- 大字号的中文标题用浅负字距（`-0.02em`）：中文方块字比拉丁字母更早被负字距挤到一起
- 微标签（eyebrow / 表头 / stat 标签）统一 12px、字重 600–650、字距 0.04em：
  在西文字体缺失时汉字会回落到系统中文黑体，此时过宽的字距会把整词拆散
- 最淡的一档文字（`--ink-ghost`）在深色主题下对底色的对比度是 4.7:1（浅色 4.3:1），
  不再有看着像污渍的灰
- 键帽字模随键帽尺寸缩放（`clamp(8px, --kb-unit × 0.23, 11px)`），不再是写死的 9px

## 重新生成词库数据

仓库已包含构建好的数据，只有想从上游重新生成时才需要这一步：

```bash
node scripts/fetch-raw.mjs       # 下载上游数据到 raw/（需要 gh CLI 与 unzip）
node scripts/build-data.mjs      # 生成 public/data/vocab/* 与 categories.json
node scripts/build-japanese.mjs  # 生成 public/data/japanese.json
```

`fetch-raw.mjs` 需要 `gh auth login`（英语词表的压缩包超出 jsDelivr 单文件限制）。
日语 CSV 直接走 jsDelivr，无需认证。

中文释义来自 `scripts/curated/jp-zh.json`（人工整理，覆盖 N5–N1 全部 7,032 词），
按假名读音为键；构建脚本会把两个读音写法（如 `いい; よい`）归一到同一个键。

数据被拆成三类文件，保证首屏不加载任何大文件：

- `<book>.index.json` —— 紧凑词条行（约 150–280 KB），进页面时加载一次
- `<book>.detail.<n>.json` —— 完整词条详情，每 400 词一个分片（约 400 KB），按需加载
- `<book>.sentences.json` —— 句子练习池

## 打字引擎怎么算

指标沿用主流打字练习工具的定义，方便横向比较：

- **WPM** = (字符数 ÷ 5) ÷ 分钟
- **净 WPM** 只统计完全打对的词；**原始 WPM** 统计实际敲下的每个字符
- **准确率** 逐键实时统计 —— 打错再改回来，那次错误依然计入
- **稳定性** = `100 × (1 − tanh(σ/μ + (σ/μ)³/3 + (σ/μ)⁵/5))`，速度波动越小分越高
- **XP 曲线** 与等级可逆：每级所需 `49 × (等级 − 1) + 100`

弱键选题借鉴自适应练习的思路：对每个键维护一个指数平滑的「打字耗时」（α = 0.1）与错误率，
给候选词按所含字母的耗时加权打分，优先练最慢的键。

按键捕获走 `keydown` 而非 `input`：这是一个面向实体键盘的训练器，需要 `event.code`
来驱动键盘高亮与指法分区。同时拦截了 Tab / 空格 / 引号 / 斜杠等会触发浏览器行为的按键，
并在焦点位于表单控件时让路。

## 可访问性

- 全局遵循 `prefers-reduced-motion`：动画与 3D 空转都会停下
- 所有交互元素可键盘聚焦，焦点环可见
- 打字区域对屏幕阅读器提供完整文本（逐字 span 标记为 `aria-hidden`）
- 颜色不作为唯一信息载体：正确 / 错误同时有下划线、删除线与底色差异
